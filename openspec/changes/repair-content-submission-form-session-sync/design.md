## Decisions

### 1. Rotate the two Form keys on identity change

Make `_form1Key` and `_form2Key` replaceable screen-owned `GlobalKey<FormState>` fields. Rename `_handleSessionRetired` to `_handleSessionIdentityChanged`, including registration/removal and accurate Dart documentation. Keep the mounted guard and unchanged-identity early return; inside one synchronous `setState` record the next identity and replace both keys with new instances. Remove `_clearEpoch`, the `ContentSubmissionFields` epoch ValueKey, and the identity listener's entire post-frame reset callback. No setter, Command, checkpoint, clear or restore belongs in this handler.

New GlobalKeys prevent reuse/reparenting of old Form elements and their descendant state. The first Form owns text/Quill; the second owns email/author/terms. The outer `ContentSubmissionFields` is Stateless and its category/event controls read current VM values; it needs no additional session epoch. Keep same-session keys stable so typing, validation, selection and Quill lifecycle are preserved.

Rejected alternatives: removing only `reset()` leaves retained contact controllers displaying stale content; remounting only the shared fields leaves the second form unsafe; an extra epoch duplicates the two key boundaries; passing Admin `hydrationRevision` remounts only selected shared fields and misses contacts/terms; ViewModel normalization hides only the empty-string symptom and changes legitimate input semantics; router/progress exemptions mask an incorrect authoritative snapshot.

## Risks / Trade-offs

- [Sliver fields are lazy] → Scroll and inspect real controller values; ensure both Forms are mounted before stale-value retirement. Avoid claiming offscreen fields exist without finding them.
- [Home/shell setup differs from marker tests] → Use the existing real router with its existing repository fakes and provided SyncViewModel; route URI alone does not excuse widget exceptions. Production router and guard must remain in the test.
- [New regression results are pending] → Production edits are gated on relevant pre-fix failure evidence. Bug B attribution remains conditional; test-first execution is the only unresolved symptom gate, not a new architectural decision.
- [SDK/global-key behavior changes] → The fixed design relies on normal subtree replacement, not reset internals; exact snapshot/UI regressions protect future upgrades.
- [Existing dirty/async/Quill behavior regresses] → Keys rotate only on identity change; preserve existing mounted-safety patterns and same-session lifecycle. Focused/full tests and analyzer comparison verify this.
- [Staged cleanup is best-effort] → Preserve existing cleanup semantics; assert old assets no longer active, not stronger filesystem/transaction guarantees.
