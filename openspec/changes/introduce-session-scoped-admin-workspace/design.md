# Design

## Context

The fetched `origin/main` is `8c0e61ea42d98641bbb57d829627171bd1a3d279`. [PR #53](https://github.com/xmattjus/moliseis/pull/53) is open at `52127fcf06e1d4f7c30d183c3752f812952b453b` and has that main commit as its merge base. The versions match the previous investigation. Main locks GoRouter 18.0.2 and the PR locks 18.1.4. Flutter 3.47.5 / Dart 3.13.4, GoTrue 2.27.2, Supabase Flutter 2.18.0, Supabase 2.16.2, command_it 9.5.2 functions_client 2.7.1 and image_picker 1.2.3 are the relevant baseline.

- **Source evidence.** `lib/routing/router.dart` redirects on auth changes, owns Login and the Dashboard/New/Edit/Progress route tree, and runs Admin exit policy through `onEnter` and `onExit`. Settings selects an auth-dependent URI, Login can replace an imperative visit, and Dashboard observes the delegate to recognize Editor return. The Dashboard's initial read can start before it is bound to auth. Its ViewModel protects several lanes from disposal and stale executions without binding all of them to a continuous authority. The app-level Editor ViewModel already listens to auth and owns command reservations, while `AdminDraftSession` serializes local changes and owns the active draft state.
- **Experimental evidence.** The reports `admin-navigation-authorization-investigation.md` and `admin-navigation-architecture-decision.md`, the characterization source, the shared harness and its PR-only auth probe were consulted in the existing investigation checkouts. The reports document 38 main characterizations, including stale Dashboard disclosure/admission, and 43/44 topology cases with the two router versions. ShellRoute cases intentionally demonstrate failures. Negative controls remove the Workspace key or use a root dialog. The extra case uses the production auth owner with controlled observations. These tests were not rerun in this planning session and do not establish production Workspace integration or server bypass. The tracked briefs in `docs/navigation/` record the earlier partial reproduction and the separate deferred-exit problem.
- **Canonical evidence.** There are no other active OpenSpec changes on this baseline. The Admin draft/staged-assets, Save/Progress, dirty-exit, stale-recovery, Dashboard and Editor archives explain why several domain guards exist. The older command-execution Save-close and no-adoption clauses conflict with the later editor contract. The delta preserves captured execution and moderation fences, replaces automatic closure with local Progress, and retains confirmed Create adoption. The Explicit Back delta retires old Admin-only Login and diagnostic scenarios while preserving ordinary public Back. The public shell, Sync, public submission, Admin staging and server Save idempotency capabilities retain their current contracts.

## Goals / Non-Goals

Separate the lifetime of private presentation from global history and from the lifetime of work. Exercise the real Settings, Dashboard, Editor and Save flow with the current owners and theme. The scope excludes general router repair, public workflow orchestration, additional backend infrastructure and speculative combinations of routes.

## Decisions

### 1. One entry and one private lifetime

Keep the stock GoRouter, four public branches, existing auxiliary routes and Sync. Settings pushes `/admin` without choosing an auth destination. That route renders Login or a safe waiting/error state until the auth owner authorizes it. Login and logout continue to use the app-scoped auth owner and its single-flight commands. Logout changes the auth state in the existing entry. A successful logout shows Login there and leaves the actual public predecessor available to Back.

Create the private Navigator, its key and its Dashboard owner inside a subtree keyed by the current authority interval, per Workspace entry. Give every new subtree fresh navigation identity. In particular, a fixed GlobalKey reused in the same frame can reparent a Navigator and defeats subtree turnover. Local New/Edit/recovery opening carries a concrete selection, not a URL. Dashboard returns are driven by the completion of a current local Editor visit or equivalent local lifecycle, independent of the boolean result. Qualify the callback before refreshing or offering recovery. Progress dismissal and mandatory removal never count as Editor return.

A fifth persistent branch would deliberately retain private navigation. A normal ShellRoute retains declarative targets and owns a fixed Navigator key. Auth gates and redirects alone do not retire those targets. PR #53's repair demonstrates the cost of coupling retirement to global route matching, restoration and public push results. Use the existing Flutter Navigator beneath the current MaterialApp.

### 2. Establish authority, invalidate it and retire presentation

- Reuse PR #53's opaque identity concept in `AdminAuthViewModel`. Set or clear the current interval before notifying observers, and let private operations compare directly with their captured identity, including during reentrant notifications. Deliberate loss, demotion, account replacement, invalid session and stream error break continuity. Ordinary token refresh and same-role user updates preserve it. SDK event snapshots can arrive after `currentSession` changed. An observation can end an interval even if live state already holds a later Admin. A stale snapshot cannot establish authority for the live user. Keep the login response a correlation witness only.
- Adapt startup and SDK invocation handling. GoTrue `setInitialSession` installs persisted data. Supabase Flutter starts `recoverSession` asynchronously, and GoTrue can complete a nonexpired same-account recovery without emitting another event. Neither a cached `currentUser` nor waiting for a second event establishes fresh Admin authority. On Admin entry validate an otherwise unverified restored session using the existing Auth user lookup for the current credentials. Correlate lookup to the originating current session and authority observation, require a non-anonymous user with strict Admin metadata, ignore superseded responses, and expose safe retry/error state. Reuse verified live authority on ordinary entry or resume. Keep this validation Admin-scoped and share one in-flight validation for the same evidence. No polling or new backend endpoint. The same correlation rule covers recovery from a stream error; rereading cached metadata alone cannot clear it. The pinned GoTrue public stream replays historical observations and exposes potentially cached initialSession evidence. Do not turn those stale observations into a fresh grant.
- Bind each private action and effect to its original presentation and interval, not whatever authority happens to be current when a deferred callback runs. Check reserved/deferred action entry, after reentrant notifications and relevant awaits, and immediately before each new privileged phase. Reject a live session/account or role mismatch at dispatch even if the corresponding async event has yet to be delivered. Bind each already-entered privileged HTTP phase to its admitted principal at the data boundary. The shared Functions client asynchronously encodes the body before HTTP, and its AuthHttpClient awaits a session before filling an absent Authorization header. A guarded repository call can otherwise be sent as the successor. Reuse per-request credentials captured from the qualified current session for that call, or the existing transport if it can prove the same binding. Keep credentials inside the data boundary, out of command state and diagnostics, and never change shared Functions auth headers. A replacement can prevent future phases while the already-entered request still settles for its original principal. Capture the interval for Logout and check again immediately before SDK sign-out. This closes the stale intent window without promising atomicity after SDK entry.
- The next reconciliation removes the retired Navigator as a unit, including its routes and overlays. No auth-driven GoRouter refresh, pop, exit vote or transition approval. Ensure a transition retaining a Workspace route cannot continue painting or exposing retired pixels, semantics, input or focus. On mandatory app removal retire that Workspace visit even if auth remains continuous. Private UI disposal and logical invalidation are separate, and operation settlement follows its own ownership. Client invalidation starts at observed loss. Server authorization remains authoritative for requests.

Pinned sources include GoTrue's auth snapshot delivery and session recovery, Supabase Flutter's asynchronous bootstrap and the Supabase auth HTTP wrapper. Supabase documents [Dart auth events](https://supabase.com/docs/reference/dart/auth-onauthstatechange) and [sign-out token lifetime](https://supabase.com/docs/guides/auth/signout).

### 3. Preserve admission, physical settlement and durable recovery

- **Dashboard.** Bind the production ViewModel before its initial read. Carry forward guards on filter/selection, load and refresh lanes, un-ignore, opening pending detail, recovery and post-mutation refresh. Keep live authority and applicable lane/execution checks even while the tree is still mounted. Prevent publication of stale rows, status, action IDs and feedback. Link Dashboard presentation and one-shot results to the current local visit. Drop duplicate observations that only distinguish committed GoRouter configuration from installed pages. Preserve the supported loading and refresh behavior, including refresh on an untouched Editor's normal return.
- **Editor and local owner.** Keep the app-level command/persistence ownership in `dependencies.dart` initially. Bind activation explicitly to the Workspace visit, authority and exact account/session/target before lookup, and recheck after lookup and around initialization/install. Reuse `AdminDraftSession` generations, serializer, exact owner and reviewed snapshot checks. Retiring a visit invalidates presentation bindings and outstanding effects without disposing the application owner or deleting work. Ordinary Exit to Dashboard and Settings leaves the app-owned active session and its explicit recovery checkpoint obligation intact while authority remains continuous. A later Workspace visit starts at a fresh Dashboard and same-session reentry binds a fresh presentation. Its old callbacks cannot gain authority through the retained domain session. A new target still refuses replacement until the matching explicit checkpoint succeeds. Mandatory Sync removal with unchanged authority retires presentation and preserves applicable app-owned obligations. An actual auth break or app owner disposal follows existing domain revocation; restart restores persisted truth.
- **Settlement.** An admitted command can be deferred and must skip I/O if its authority is gone at entry. Once I/O has started it can finish once for the original owner. Preserve existing command release, error reporting and serialized local commits that were already started and can safely commit under the original exact owner. Keep physical reservations through their existing settlement barrier, including across same-account reentry. Reentry or explicit Retry cannot duplicate an incompatible in-flight operation. Existing Save discards a late field response before new adoption/confirmation phases if authority has ended. Preserve the already written pending intent for explicit replay/read-back instead of promising post-revocation adoption or starting another write. A remote Create that may have committed retains its client UUID, and an ambiguous Update still uses existing read-back/conditional-write policy. No silent retry, replacement mutation, rollback claim or additional remote phase on behalf of retired UI.
- **Draft and picker.** New and matching Dashboard rows use existing account/target activation for ordinary durable drafts and staged/pending work. Use the Dashboard's explicit offer backed by `loadNavigationDraft(accountId:)` and `loadDraftBySession` for eligible interrupted picker sessions. Read and install only a current, exact owner, preserving Create adoption. Durable draft fields, staged files, receipts and pending writes stay in their existing stores. The picker still checkpoints before launch, uses the original live activation and request nonce, and compares nonce on cleanup. Resume keeps a valid pending Future. Revocation/explicit abandon drops its publication authority and releases only its own reservation. Process death loses the Future and there is no attributed native result to attach. Admin never drains `retrieveLostData`; Public's pinned lost-data behavior and its known native attribution limits remain. No automatic checkpoint on mandatory retirement and no recovery promise for edits that never became durable.

### 4. Ordinary exit, local Progress and private feedback

Use the production theme's Material transitions, which select Android predictive and iOS Cupertino transitions. A nested Navigator can use `NavigatorPopHandler` and local `PopScope` with ahead-of-time pop eligibility. Gate delegation and the callback against the enclosing Workspace route's actual visibility/current ownership, including during a cover or interrupted gesture. Dirty iOS edge gestures can be disabled without callbacks, so explicit Back must enter the local decision path. Use the ordinary explicit Back helper at the global Workspace landing using its enclosing Page context; local Editor Back operates on the owning local Navigator. Preserve Escape, root system behavior and Home fallback. Verify the actual adapters and Navigator delegation with system Back, not merely the existence of an on-screen button.

Use one current local dirty decision. Before any await, capture the exact source and reviewed fields, baseline, revision, recovery state and activation using the existing review API. Retain single-flight Cancel/dismiss, Discard against the effective baseline and Save and Exit as a local checkpoint of the reviewed snapshot. Check again at serialized execution and before the exact local removal. A superseded completion cannot pop a covered/replacement Editor or underlying Dashboard. Running Save and existing local operation barriers refuse ordinary exit. Mandatory loss revokes decisions and their effects regardless of local pop eligibility. Remove permits and match-tracking that only coordinate global Editor arrival/departure. Preserve normal moderation closure and existing moderation revision fences. A synchronous local entry reservation and the current visit bind competing Editor opens and recovery attempts, including callbacks executed before a frame or during a transition.

Prefer a fullscreen Editor-owned Progress presentation driven by the matching admitted execution. Keep the Editor mounted, make Progress the only interactive and accessible surface while it is shown, route explicit/system Back to that surface, and disable native gestures that would pop the Editor while Progress owns Back. Running Progress refuses departure. Terminal Back dismisses Progress and returns to the same authorized Editor with appropriate focus. Preserve partial/unknown/local repair/unexpected outcomes and explicit phase-qualified Retry. A normal local route is a bounded fallback if the real theme or semantics require a fullscreen native modal surface, with the same lifetime and no independent restoration or dispatch.

Use the nearest Navigator for all private dialogs and modal sheets, including shared dialog helpers whose default targets root. Anchor menus, overlays and focus to the private subtree. Use a Workspace-local `ScaffoldMessenger` and reuse existing snackbar appearance and presentation behavior. Within that messenger recovery still yields to ordinary Workspace messages, with visit-local suppression based on explicit dismissal or verified exact Editor initialization, not mere navigation acceptance. The shared helper currently targets a global key. Provide only the small local targeting needed for Admin, including a cancellable local recovery offer with existing queue/dismiss behavior. Avoid mounting a second app or adopting PR #53's global queue retirement machinery. Verify public feedback is neither withdrawn nor reordered by private retirement, and preserve selective Replay masking on newly composed private views.

### 5. Global surface, restart and Sync

Remove obsolete Admin route constants, names, parameters, Login replacement and auth redirect/refresh plumbing. Remove Editor and Progress route bindings, legacy restoration and Admin-specific deferred exit/match logic. Audit existing production callers and test harnesses. Keep public Content Submission transitions, Gallery ownership/error handling and the public explicit Back logic with their own present-day invariants. In particular, the deferred-exit investigation records a public replacement regression tied to previously removing a separate workaround. Do not delete public protection by association.

Keep stock public restoration. Select Home on restart if normal restoration cannot retain only the Workspace entry safely. An ordinary restored `/admin` entry re-enters through safe auth and a new Dashboard, with no private restoration scope, restorable private push, saved Editor/attempt ID or private history decoder. Existing generic router errors and safe fallback handle unmatched or unrecognized old state.

Use the existing initial/fatal Sync redirect and retry; verified returns can target `/admin` or the normal safe destination. `_redirectForSync` observes the shared running command, and `SyncViewModel` starts due Sync on construction and exposes manual/Retry paths. Exercise actual triggers and committed replacement in the production router. Retirement follows actual mandatory takeover or removal. Same authority on return grants a fresh presentation for a removed Workspace and no new powers to background Sync. Preserve existing public Sync behavior and generic `from` validation; no stack repair.

### 7. GoRouter decision and durable design rule

Keep GoRouter 18.0.2 for this change. Its cache and 18.1.4 were compared. The latter's [active-branch fix](https://github.com/flutter/packages/pull/13606) changes the shell builder. Main's public NAV-01 in `test/routing/geo_map_route_test.dart` is explicitly skipped. The previous unskipped dependency-only comparison reports 18.0.2 incorrectly consumes Map-root Back and 18.1.4 passes with the inactive Post stack intact. That evidence is narrower than physical predictive Back. [Flutter #188018](https://github.com/flutter/flutter/issues/188018) and [packages #11910](https://github.com/flutter/packages/pull/11910) track native inactive-branch behavior. [Flutter #156809](https://github.com/flutter/flutter/issues/156809) and [packages #12112](https://github.com/flutter/packages/pull/12112) track deferred exit approval. Both issues and both linked candidate PRs were open when checked; the active-branch builder fix was merged. The Admin Workspace removes its dependency on those approvals; none is a prerequisite for its ownership boundary. Preserve the independent public NAV-01 gate.

Place the permanent principle in root `AGENTS.md`, beside the architecture/navigation guidance, during implementation. Design navigation around supported user journeys, semantic identities and authority, lifecycle, recovery and presentation ownership. Independent owners should not interfere. Use artificial interleavings only as proportionate isolation controls when they expose a real boundary. Reassess earlier workarounds against their actual public responsibilities before removal. This rule applies to future designs without opening a navigation audit here.

## Risks / Trade-offs

- **Stale UI or wrong account at dispatch.** Test immediately after logically observed loss without pumping a frame, then check retirement after reconciliation. Test the live SDK credential mismatch and queued observations independently. Server `admin-content-submissions` has JWT verification and calls Auth `getUser()`; it rejects missing, anonymous or non-Admin users before constructing the privileged store. Existing RLS and service-role RPC restrictions stay in place. Static inspection does not establish latency or deployed previous-token behavior.
- **Retired operations and recoverable state.** Reuse the app-level owners to preserve physical settlement, exact pending identity, checkpoint serialization and recovery. Regression tests should hold persistence, remote outcomes and original picker callbacks across reentry. Distinguish already-started local commits from future phases and UI publication.
- **Flutter lifecycle and UX.** Real Navigator/PopScope dispatch, material and Cupertino transitions, focus/semantics, global vs local overlays, an in-progress Back gesture and actual Sync replacement require integrated and physical verification. Use a bounded visibility/control test, not a matrix of public workflows.
- **Recovery discoverability.** Retiring private restoration removes automatic return to old UI. The current Dashboard recovery offer and New/Edit entry paths must make account-owned work accessible. Report unavailable or ambiguous intent safely and retain the underlying work.
- **Public regression or release-gate erosion.** Existing public Back, NAV-01, Sync, Replay and independent physical/profile release checks retain their own evidence requirements. No public workaround or spec relaxation is justified by an Admin pass.

## Migration Plan

Introduce authority safeguards first, then integrate one production thin slice from Settings to terminal Progress and local return. Replace the global Admin entry/callers and remove old Admin routing in the same cutover. Verify durable pre-change data through the existing account-qualified stores, without URL migration or bulk data transformation. Complete focused checks and independent review before merge readiness. Physical and runtime acceptance remain explicit tasks and public release gates. Review and publish via a new PR against main. Keep PR #53 open and unchanged; any later closure is an owner action after the new PR merges. If candidate integration fails, hold release and fix it on the new branch. An earlier build or PR #53 cannot substitute for release acceptance.
