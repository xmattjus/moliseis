### Installed dependency behavior

The lockfile and installed sources identify Flutter **3.47.5** (framework `6a19cca56475dbfba1478ee68d7bd0c2ef891da1`, Dart **3.13.4**), `go_router` **18.0.2**, and `material_ui` **1.5.0**. Installed `go_router` `match.dart` compares route, matched location and page key; `delegate.dart` calls outgoing `onExit` for differing matches and independently for native pop. Therefore a different ID changes the match even though the route definition is unchanged. Query-only session changes can reuse the match and skip `onExit`.

Installed `router.dart` documents `onEnter(current, next, router)` before redirect resolution, once for the literal incoming URI. It cannot be treated as a guard of every redirect destination. Installed `material_ui` `dialog.dart` supplies constrained `AlertDialog`, scrollable content and action overflow. [Official go_router changelog](https://pub.dev/packages/go_router/changelog) corroborates guard availability; installed source, not later documentation versions, governs this plan. No dependency upgrade is proposed.

## Goals / Non-Goals

**Goals:** Protect uncheckpointed fields through one explicit policy; preserve remote admission and recovery safety; share presentation without coupling Public and Admin orchestration; retain normal native clean navigation and accessible desktop use.

**Non-Goals:** No generic navigation framework, parallel session manager, new DI, backend/migration work, draft schema change, owner retirement, automatic remote Save, generic draft deletion, picker provenance redesign, new package or broad form refactor. Do not apply or reinterpret historical `improve-admin-submission-editor-workflow`. Do not synchronize canonical specs in this PR.

## Decisions

### 1. Keep five independent facts

| Fact | Existing owner | Exit consequence |
| --- | --- | --- |
| Local uncheckpointed fields | session C differs from E | Offer the three-choice field dialog when otherwise admissible |
| Durable staging / receipts | retained exact-owner descriptors and receipt evidence | Preserve; alone does not prompt |
| Remote work / unresolved field intent | R, durable field intent, VM moderation `isDirty` | Preserve; no remote confirmation or intent settlement from exit |
| Recovery checkpoint obligation | `recoveryCheckpointRevision` | Survives page removal; still blocks unsafe replacement |
| Running work / transition ownership | existing local arbitration, VM reservations, route decision slot | Refuse ordinary exit before prompting |

Expose read-only local field dirtiness through the existing VM and preserve `isDirty` and its moderation callers. Do not infer cleanliness from owner existence, `currentMatchesDisk`, remote equality or asset count.

### 2. Local checkpoint is Save and Exit

At the exit decision boundary, before showing the dialog, capture one immutable reviewed checkpoint context: exact account/session/target and activation, reviewed editable C=A, reviewed E, `fieldRevision`, and the existing P/R, accepted-remote revision and recovery-checkpoint revision identities relevant to the decision. Capture these facts together from the initialized session; do not reconstruct them from live state after the choice. Carry this same context through an Exit-specific ViewModel checkpoint entry to `AdminDraftSession` using its existing local arbitration and Result conventions, never `requestSave`. Preserve incomplete coordinates, event values and rich text.

The current ordinary `checkpointLocal()` passes no reviewed context: domain `checkpoint()` awaits initialization and local serialization, then `_checkpoint()` captures the then-current `_state`. Reusing it unchanged would permit unreviewed B to become P/E and pass a final clean-state check. For Save and Exit, validate the captured context **inside the serialized action, after earlier local work settles and immediately before selecting the draft or writing**. Require exact activation/owner, unchanged field revision and reviewed C/E plus the captured baseline/recovery identities, including changes that leave C equal. Refuse before any write or baseline effect if superseded. Select only reviewed A as the draft's field snapshot; never substitute newer `_state.current` or silently recapture a fresh review. Preserve unresolved write/navigation metadata and existing recovery proof rules. Validation solely in the router, in the ViewModel, or before an await is insufficient. This is a narrow Exit-specific admission path: ordinary checkpoint, picker, remote Save and recovery callers retain their existing capture timing and compatibility; no generic versioning framework, new persisted revision or separate persistence coordinator is needed.

Once persistence of reviewed A has begun, it may finish under its original owner without rollback because of later typing. Successful settlement records P=A and E=A only while that activation remains current; newer C=B stays B and uncheckpointed. It must neither overwrite B nor mark B confirmed. Revocation/replacement permits only the already-started original-owner durable write, with no publication or private effects in another activation. Recovery obligations clear only under existing matching captured proof, never because the exit review was stale.

The owning router invocation may return affirmative permission only after successful confirmation of reviewed A, with the same route/VM/account/session/target/activation authority, unchanged reviewed field revision and C=A, and current fields checkpoint-clean against confirmed P/E=A. Allow only this operation's own P/E advancement and matching recovery-proof settlement when checking the reviewed context after success; unrelated baseline/recovery changes invalidate permission. A clean-state check alone is not proof of reviewed persistence. Failure, superseded review or newer edits retain the editor and all local work, with any error shown only under current private presentation authority.

Admin supporting copy, expressed here in English and rendered using existing Italian UI conventions: “Save and Exit saves these fields to a local draft on this device. It does not save the submission remotely. Use Save to send changes to the server. Discard removes only field edits since the last local checkpoint or accepted remote baseline; staged photos and previously saved draft work are retained.” Keep Public labels/meaning and current nonaffirmative dismissal behavior. Neither local choice performs remote validation, Create/Update, Cloudinary upload, association, deletion or moderation.

Remote Save as the exit choice is rejected: it would couple leaving to validity, network availability and multi-phase mutation, bypassing Plan 2 admission/Progress and Plan 3 unresolved-outcome rules.

### 3. Add a narrow field-discard operation to the existing session

Proposed API names are provisional: VM `discardLocalFieldChanges(activation: ..., reviewedState: ...)` delegates to a session operation inside existing local ordering. Capture the immutable reviewed C/E, field revision and baseline/obligation identity at dialog admission. Validate exact account/session/target/generation and unchanged reviewed state on entry to arbitration. Refuse if superseded or conflicting work has not settled. On success set **C := E** only, advance local intent revision when fields change, and publish through the VM's ordinary field-change notification/invalidation path. Invalidate stale recovery observations, moderation acknowledgements and previews that depended on the old fields; do not reset the whole VM or pretend remote work was saved.

P, its recorded R/intent/navigation metadata, current accepted R, staged bytes/order/receipts, owner and recovery obligation are unchanged. No repository call is needed. Replaying P, using remote reconcile, clearing context, or deleting/recreating a draft would violate this boundary.

Examples: ordinary hydration P=A, E=B followed by typing C discards to B, leaving P=A. Explicit recovery Accept P=A, E=B followed by typing C also discards to B, retaining the pending obligation. A remotely unsaved but checkpoint-clean E=L remains L. Discard failure is a typed refusal under existing Result contracts, not a generic catch that rewrites unexpected throws.

### 4. One Admin decision owner, two narrow route adapters

Keep a router-lifetime, Admin-specific decision slot modeled on Public ownership, with an opaque invocation token and captured source route visit/configuration, VM, account/session/target, activation and reviewed field state. No persistence lives in this slot. It is not another session manager.

`onExit` receives the root navigator context, not the source editor context. Extend the existing `AdminSubmissionEditorRoute` binding with narrow register/unregister callbacks supplied by its router builder. In `didChangeDependencies`, register an opaque visit identity and the actual editor `ModalRoute`/navigator handles plus bound activation; refresh or revoke the registration on rebinding, adoption, replacement and disposal. Register only the editor presentation (`child == null`), never the Progress observer binding. Unregister by identity so old disposal cannot clear a newer visit. The policy reads that registration rather than calling `ModalRoute.of(onExitContext)` to infer the editor. Pass the policy-owned explicit Back/moderation-close initiation callbacks through this existing binding to the screen; no new Provider or global registry is needed.

- Install the same `onExit` policy on New and Edit for actual removal, native pop and different-ID navigation. Each invocation owns its own Future/result; a concurrent invocation returns false immediately. The affirmative boolean belongs only to its original router continuation.
- Add a synchronous, non-authorizing `onEnter` preflight for incoming Admin target/session replacement while a recovery checkpoint obligation exists: refuse before `onExit`, without a dialog or baseline effect, retaining actionable access to the active editor. This includes dirty-plus-pending A→B, unlike A→dashboard which retains the owner and may require the field dialog. Dashboard→B still uses the existing activation refusal if another retained owner has an obligation. This classification grants no affirmative permission and needs no mutable destination handoff.
- Use the same narrowly scoped top-level `onEnter` adapter for **query-only session identity rebinding**, where match equality can skip `onExit`, and to refuse incoming competing parser navigation while a private exit slot is occupied. It captures its own literal destination and invokes the same decision policy only when needed. Ordinary non-Admin navigation stays untouched. Initial restoration with no outgoing editor does not prompt. Query changes that retain the exact active identity are not exits; invalid/foreign/mismatched hints still fail closed under existing route-binding rules without mutating source work.
- Different-ID changes are handled by `onExit`, not by adding a second policy to `didUpdateWidget`. Route binding remains the final activation/target-agreement backstop. Existing domain activation guards cannot be removed.
- Do not hand an affirmative result from `onEnter` to `onExit`; their scopes are disjoint. Do not authorize through a mutable “last requested destination”, shared affirmative Future, global allow-next-pop flag, or replayable permit. Two parser admissions before dialog display must still have exactly one successful owning continuation.
- Distinguish pushed retained pages from replacement using actual route configuration and the installed router's navigation state. Pushing Progress does not remove the editor; popping it is owned solely by Progress. Keep its session/attempt and in-flight Save guard. A replacement that removes both pages still obeys their guards.
- Hold successful ownership until the owning removal/rebind commits or is proven canceled, including a post-frame release as Public does. Handle no-op navigation, redirect, rejected rebind and unmount cleanup without leaking a slot or releasing a replacement slot.

No blanket top-level async guard is needed for all navigation. A generic router coordinator would broaden the problem unnecessarily.

### 5. Policy order and authority across awaits

1. **Security first:** direct auth revocation/account mismatch invalidates private effects synchronously and permits required security navigation, independent of dialog, checkpoint and physically settling HTTP. Retire only the captured dialog route using its captured navigator, never `pop()` whichever route is top. A stale ordinary continuation returns false; the separate security transition is not blocked by its slot.
2. **Retained-page and authorized moderation cases:** a normal progress pop is not editor exit. Current successful moderation closure carries a one-use source/activation/execution-qualified reason into the same exit policy; it cannot become a generic bypass. Save completion never uses this reason.
3. **Admission barriers:** check existing Save/mutation reservations, picker/acquisition/local settlement and initialization/hydration barriers before showing a dialog. Do not wait on remote mutation as part of exit or make an exit choice bypass its reservation. Reuse existing VM admission machinery for a narrow exit-boundary reservation so new mutation/picker/recovery actions cannot begin under a decision; release only that reservation. No new Command hierarchy or blanket ban on existing checkpoint behavior is required.
4. **Recovery replacement:** a pending recovery checkpoint obligation refuses different target/session replacement with existing actionable return/checkpoint recovery, without an automatic dirty dialog, discard or checkpoint. Pure page removal can retain the activation/obligation. Same-session rebinding reuses both. If C differs from E during a pure page exit, the field dialog applies, but discard cannot clear the obligation.
5. **Fields:** C=E permits ordinary removal with no field prompt/write. Otherwise capture the reviewed field/baseline revision and show the shared dialog. Cancel/null refuses; checkpoint/discard success proceeds only while authority and relevant cleanliness still hold.

Validate captured VM identity, current Admin account, exact activation (including A1→B→A2), session/target and source visit/configuration before displaying the dialog, after its result, before local action admission, after its completion and before affirmative return. Observe the exact dialog route while open; an unexpected covering route permanently revokes that decision. After dismissal require the original source route to be current with no intervening coverage. Raw Navigator pushes can bypass `onEnter`, so configuration equality alone is insufficient. A stale result cannot checkpoint a replacement activation, discard newer input, authorize another target, publish an error, or pop an underlying page.

Follow the existing mounted-safety skill during implementation: check `if (!mounted) return;` immediately after async gaps in State callbacks and capture owner/auth/router/dialog references before await. Keep disposed State.widget/context out of late effects; raw post-dispose Command throws are not made safe by global reporting.

### 6. Platform initiation and shared dialog presentation

Admin route/editor presentation initiates AppBar Back and desktop Escape through the router policy. Modal Escape/Back cancels only that modal. Mirror Public's iOS-specific `PopScope` and transient explicit-Back initiation: dirty fields or an owned decision disable native swipe before gesture start; clean idle native swipe remains available. The temporary explicit initiation is scoped to the exact source visit/activation and cleared after dispatch; it does not itself authorize removal. Keep Android system/predictive Back on the same router decision path. Do not apply a permanent dirty `canPop:false` to every platform and accidentally suppress the route policy.

`lib/ui/core/ui/unsaved_changes_dialog.dart` contains the typed enum/result and widget only; callers own showing/dismissing the modal and acting on its result. Widget action callbacks only return their typed choice through the dialog navigator. No VM, Command, repository, route-name or persistence imports. Optional copy is plain presentation data, not executable save callbacks.

Use `context.appShapes.circular.cornerExtraLarge`, scheme surface/onSurface/onSurfaceVariant and primary action roles, and theme headlineSmall/bodyMedium/labelLarge with app typography geometry. Reuse existing button themes. Window classes are compact <600, medium <840, expanded <1200, large <1600, extraLarge otherwise. Use class spacing (16 compact, 24 otherwise), safe view insets and width clamped to available space with a readable 560 dp cap across wider classes. Let actions wrap/stack and content scroll; do not set fixed height, shrink accessibility text, or scale the dialog to desktop width. Default focus goes to Cancel, with modal closed-loop traversal and visible focus. Preserve accessible touch targets and semantic labels. Public keeps the existing title/action wording and exit orchestration.

## Risks / Trade-offs

- **Router callback races and query-only reuse** → invocation-owned results, scoped `onEnter`, source/dialog coverage checks and production-router race tests. No dependency patch/upgrade is assumed.
- **P and E diverge, including explicit acceptance** → C:=E only; recovery obligation preserved independently. A clean exit does not imply physical durability of accepted fields.
- **Plan 3 refusal UX versus new exit consent** → preserve no-dialog recovery-obligation refusal and actionable recovery. Only ordinary uncheckpointed-field refusal is refined into a user decision; the modified canonical requirement is copied in full in this delta.
- **Admission during dialog or local completion** → existing VM reservation seam, reviewed revision validation and post-checkpoint dirty check; UI absorption alone is insufficient.
- **Runtime recovery obligation is not a new durable journal** → same-session route removal retains the app owner; real process restart still restores P/historical R and requires fresh authority, exactly as Plan 3. This change does not promise that uncheckpointed B survives process death.
- **Discarded fields can invalidate dependent UI evidence** → use the existing field-change invalidation path without mutating durable intent/receipt state.
- **Native gesture behavior cannot be established by planning** → explicit automated/native separation and the mobile native smoke gate above before release.

No unresolved material contradiction remains in the intended behavior. Native outcomes and the approved mobile acceptance decision are recorded in [verification.md](verification.md); completion of the revised gate does not imply full-platform verification or replace the independent implementation review before merge.

## Migration Plan

The original implementation sequence was local state operations, shared presentation, route integration and focused regression tests, followed by broader Flutter analysis/testing. That implementation has been performed in this PR and all 22 tasks are complete under the approved Android/iOS mobile gate. Completed automated/native evidence and the subsequent independent full-diff review are recorded in [verification.md](verification.md). Native macOS smoke remains NOT VERIFIED and non-blocking; the documented physical-device and backend/storage verification limits remain unchanged.

Canonical specification synchronization and archival are reserved for a later, separately authorized documentation workflow after this implementation PR. No data migration or backend deployment is involved. A later rollback reverts route/dialog integration while retaining the existing durable sessions and files; it must not erase checkpoints or reinterpret unresolved writes.
