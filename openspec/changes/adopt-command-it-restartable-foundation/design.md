## Goals / Non-Goals

Goals: close concurrency and error-routing architecture now; prove the primitive before consumers; retain Result boundary and distinguish idle/success; make only authoritative synchronous commits; eliminate only tested redundant guards.

Non-goals: replacement state-management, generic scheduling/sequential/concurrent/droppable policies, retry framework, restartable runAsync, future-returning public restartable execution handles, eager migration of all commands, Post/nearby redesign, mutation cancellation, backend changes, or creating the second change. The legacy command file remains with current behavior and tests.

## Decisions

### 1. Thin Result integration and ordinary command lifecycle

Add `lib/utils/result_command.dart` importing command_it under an alias to avoid collision with domain Error/legacy Command. Define `typedef ResultCommand<P,T> = command_it.Command<P, Result<T>?>`. Factories `createResultCommand<P,T>` and `createResultCommandNoParam<T>` accept actions returning non-null Future<Result<T>>, initialValue:null, includeLastResultInCommandResults:false, notifyOnlyWhenValueChanges:false, constant safe debugName, explicit errorFilterFn returning ErrorReaction.globalHandler. Thin extensions project a `CommandResult<P?,Result<T>?>` into idle, completed, domainError, unexpectedError, hasFailure; do not introduce base classes Command0/Command1 or a second result/error hierarchy. Result itself is unchanged.

| Snapshot | Meaning |
| --- | --- |
| !isRunning, data==null, error==null | Idle / never executed, including explicit invalidate neutral state. Not completed. |
| isRunning | Running, terminal projections false, previous VM collection may remain visible in memory. |
| !isRunning, error==null, data is Success<T> | Completed, including Success<void>(null) and Success<T?>(null): outer Result object remains non-null. |
| !isRunning, error==null, data is Error<T> | Domain failure, original Exception preserved; no automatic command global reporting. |
| !isRunning, error!=null | Unexpected runtime terminal command error handled by upstream routing, original Object and stack trace preserved separately from Result. AssertionError retains upstream rethrow policy and is not projected as an ordinary terminal UI failure. |

Observe `results`, not Command itself, for execution states (value listener may not run on error). All migrated UI failure branches combine domainError and unexpectedError. Ordinary run/runAsync/isRunning/isRunningSync retain audited upstream single-flight/join semantics; no custom concurrency wrapper for ordinary commands. Tests cover runAsync joining and disposed-value completion so consumers never treat disposal completion as success. Do not call runAsync when restricted with no accepted execution.

Post decision: ordinary fetch/commit separation WOULD suffice for identity loads: immutable fetched content, results listener owns synchronous commit, listener detach prevents late notify. Nevertheless an ordinary raw Command cannot be disposed early safely for a late throw or a live progress handle in audited 9.5.2. Post's mixed legacy nearby contract would also retain _disposed and its shared UI adapter. Migrating it now would need an additional ordinary owner/deferred cleanup policy with no necessity for the first-wave proof. Therefore do not migrate Post at all; preserve ValueKey((id,type)), near partial-error behavior and NAV-07 tests. The ordinary factories are proven directly and are used by restartable children; no artificial extra consumer is added. This is a fixed scope decision, not implementer discretion.

### 2. Global reporting uses AppLogger exactly once

Add `lib/utils/command_configuration.dart` with `configureCommandReporting(Logger logger)`; production calls it with existing `_logger` AppLogger in lib/main.dart before any app command construction, after binding initialization. The Logger interface permits MockLogger tests; no second logger is constructed. Set globalExceptionHandler to logger.log(CommandExecutionFailed(...), error:commandError.error, stackTrace:stackTrace). Add event in `lib/utils/logging/events/command_events.dart` as `part of 'package:moliseis/utils/logging/log_event.dart'`, register its part directive in `lib/utils/logging/log_event.dart`, and import that library (LogEvent is sealed; a standalone subclass/import of a part would be invalid; no barrel change), level error, name `command_execution_failed`, data containing only allow-listed constant debug name (unknown => `command`). Do NOT log CommandError.toString(), CommandResult.toString(), paramData, originalError wrapper or arbitrary name supplied by user input. Original thrown Object is the attached exception; parameter values are never appended. No separate Sentry capture or FlutterError.reportError for migrated caught errors; AppLogger owns Talker and enabled-flag Sentry behavior.

Set Command.reportAllExceptions=false. Do not assign Command.assertionsAlwaysThrow: retain the upstream true default and fail-loud development/test policy. StateError, TypeError and other unexpected runtime failures handled by upstream routing remain terminal + globally reported; AssertionError is rethrown before filters and must not become not-found feedback or a normal command error. Preserve false debugErrorsThrowAlways without new use of that deprecated API. Use explicit per-factory globalHandler reaction; do not globally replace unrelated default filters or enable localAndGlobal plus mandatory reports. Leave detailedStackTraces default true, useChainCapture default false, loggingHandler unset (otherwise it could leak params). Command error listener handlers must not log the same failure again. Any unexpected error thrown by a separate commit listener is a different failure, not a duplicate original command exception; keep commits simple and do not install parallel telemetry.

Global configuration tests save/restore mutated statics and handler in teardown. A recorder observes exactly one error event and original stack, no args or wrappers. Existing AppLogger tests already isolate Sentry; extend them for enabled/disabled reporting of the new event rather than building a new telemetry harness. Domain errors do not trigger global hook; stale/latest handled runtime throws do once. Assertion tests observe the actual upstream uncaught/rethrow path using a scoped test error observer that records/rethrows as appropriate, never by disabling assertionsAlwaysThrow in production or converting assertions to Results. Configuration tests assert the default remains true and that configuration does not alter this setting.

### 3. One composed RestartableCommand, not a generation state machine

Add `lib/utils/restartable_command.dart`: `RestartableCommand<P,T>` owns a single-subscription intent controller, switchMap subscription, public results ValueListenable<CommandResult<P?,Result<T>?>>, UI isRunning ValueListenable<bool> and synchronous logical isRunningSync. API: one constructor for ordinary Result action, `void run(P)`, `void invalidate()`, `void dispose()`. No public runAsync/callable await, queue, restrictions, scheduler or custom droppable mode. Restartable admission accepts every intent while alive; it does not expose child's canRun as a busy rejection. Expose no private children to callers. First-wave consumers read results; isRunningSync is coordination only.

Use an immutable per-intent envelope with identity and a private child owner (authority/settled/cleaned flags and result listener). This is lifecycle bookkeeping around switchMap, not a numeric generation-driven execution engine. `run` synchronously revokes the old envelope, replaces authoritative envelope and logical running state, then adds it to the intent stream. `invalidate` does the same revocation and enqueues a neutral intent (no child), logical running=false and blank nullable Result state. Enqueue/public updates must not publish synchronously during widget builds. Back public results/isRunning with ordinary ValueNotifiers updated from scheduled microtasks; all scheduled callbacks recheck envelope identity and wrapper alive immediately before EACH public notifier update, including between results and running updates. If a terminal results listener reentrantly calls run(B) or dispose(), the remainder of A publication must not set running=false or touch a disposed notifier. isRunningSync updates immediately; no VM/UI listener subscribes to its synchronous notifications. Thus B is authoritative before run(B) returns even if stream delivery/cancellation yields. B loading replaces old terminal state without an A-driven idle transition. Getter snapshot delivery is asynchronous as with upstream UI notifications.

`switchMap` convert ONLY constructs a lazy inner StreamController, with no child.run yet. OnListen starts one child for an authoritative live envelope; stale queued envelopes close without repository work. Inner subscription cancellation marks stale and disconnects forwarding synchronously; its onCancel returns void/already-complete Future, never the repository Future. Stream forwarding also checks envelope identity to reject data queued before B. Output stream uses normal deferred delivery; no synchronous controller reentrant add. Repeated identical params remain distinct intents, not equality-based deduplication.

Every real execution uses one ordinary child produced by the Result factory with the same Result/error settings. No WithProgress factory, ProgressHandle API or external cancellation token adapter is implemented. Attach a private terminal results listener BEFORE child.run(param). It forwards loading/terminal snapshots only while authoritative and connected; private terminal cleanup observation remains after forwarding cancellation. Do not start queued obsolete children. For a child already started but superseded before delayed action entry, execute the captured action with authority revoked. Physical work may start stale but never commits. No fabricated Result<T> value and no cancellation exception injected to global reporting.

On authoritative terminal delivery update logical isRunningSync=false before scheduling public terminal publication. Close the inner controller after terminal forwarding (or immediately on forwarding cancellation); this close must never wait on the private child. Keep child alive through physical action AND upstream terminal error routing. Use private results terminal delivery, not isRunningSync false alone, to detach its terminal listener and schedule child.dispose exactly once (outside notifier dispatch); Each child runs once: its loading→terminal results necessarily differ, so private terminal observation does not depend on Command value notification mode. notifyOnlyWhenValueChanges=false concerns the Command value notifier, not its results notifier. A child canceled before onListen was never constructed; no disposal owed. Superseded or wrapper-disposed children continue to private terminal observer and global error filter for handled runtime failures, then cleanup. Upstream assertion rethrows have no terminal results snapshot: also observe private child.isRunningSync solely for cleanup. After observing a started child’s true→false running transition with results still loading, schedule a zero-duration event-turn cleanup check, allow queued terminal notifications to drain, then retire the child once if no terminal snapshot exists. Both normal and fallback cleanup remove the private result/running listeners and close the inner forwarding controller before disposing the child; initial false state must not trigger cleanup. The assertion path does not promise a normal terminal UI snapshot, and tests exercise it through run(), not an await of runAsync that upstream cannot complete on this rethrow path. This cleanup fallback must not swallow/re-route the upstream assertion, fabricate Result/error feedback or publish stale state; leave the uncaught assertion in the parent development/test error path. Test the assertion path explicitly, including exactly-once child cleanup. Normal success/runtime-error publication remains driven by results, never by the running fallback. A never-settling noncooperative Future can retain its private child indefinitely; correctness does not depend on settlement. Avoid references from private action/cleanup closures to ViewModel; capture repository/use-case dependencies directly, not `this` callbacks that mutate state.

After wrapper dispose: mark closed/revoke authority first, cancel forwarding/outer subscriptions, dispose public notifiers, close intent controller; keep only private in-flight cleanup observers until settlement. Queued publication callbacks check closed before touching disposed notifiers. Wrapper dispose is idempotent; children are individually disposed once. No public output or application commit afterward. Ordinary child.cancel() is a no-op; foundation v1 promises logical subscription cancellation and authority revocation only, with no physical/cooperative cancellation support. Do not await physical cleanup from public dispose. Upstream delayed 50ms notifier teardown is accounted for by fake-clock tests, not copied as a new lifecycle.

Alternatives rejected: one ordinary command cannot start B while A runs; two selection lanes violate cross-type ownership; disposing A loses lifecycle/reporting; cancelable Future requirements do not fit local repository Futures; a generation state machine duplicates upstream/switchMap semantics. Minimal immediate envelope identity fencing IS necessary because switchMap pauses outer while awaiting cancel and both command_it/public notifications are deferred; switchMap remains the execution-stream policy.

ProgressHandle specialization is explicitly deferred under YAGNI because neither first-wave consumer needs it. A future real consumer must define its cancellation contract before adding support: expected token cancellation must not be mistaken for an unexpected telemetry error, cancellation-before-reset must be covered, and correctness must still be independent of cooperation. The original cooperative-cancellation test case is removed from v1 acceptance by this review decision, not marked passed or silently omitted.

### 4. Async work returns data; only authoritative completion commits

Repository overlap safety was checked in `lib/data/repositories/search_repository_impl.dart`: although searchPlaces/searchEvents return Futures, each current phase has no internal await between rebinding cached _cityQuery/_placeQuery/_placeCategoryQuery, find and materialization. Events builds local event queries and rebinds city text before its find. Separate logical requests can interleave only between these synchronous phases, not while shared parameters are being consumed; each phase rebinds its own query text. Keep Result.zip2 sequential place→event order and do not introduce Future.wait or repository refactoring. A future await inside a shared-query phase would need repository-level ownership re-audit. Current production requires no data-layer change.


Search commands become `RestartableCommand<String,List<ContentBase>?>`: valid action captures SearchRepository and returns repository Result mapped to nullable-list type; invalid short query returns Result.success(null), without repository calls. This means terminal no-op is distinct from never-run (outer Result is non-null) and from valid empty results (empty list). Existing _results/_suggestions lists stay unchanged while running/error/short query. In constructor register two results listeners before any run; each synchronous terminal Success with non-null list atomically assigns its own collection and notifies once. Handled unexpected runtime errors and domain errors never commit; assertion failures preserve upstream development policy. Do not notify for null no-op. Results and suggestions remain separate ownership domains because they update separate collections/consumers.

Remove _search's commit callback and its disposed guard only for migrated reads. Keep _disposed in VM for history and its optimistic rollback. dispose sets that existing guard, removes both completion listeners, disposes both wrappers, then super.dispose. Legacy history command ownership is not changed incidentally.

Search UI/call-site updates use `.run(query)`, listen to `.results` and thin snapshot projections. `router.dart`, SearchResultScreen retry, GeoMap modal search and GeoMapScreen search calls stop awaiting/unawaiting restartable calls. No fake completed Future shim to preserve execute signatures.

AppSearchAnchor currently awaits a debounced execute Future and uses _currentQuery to discard late options; empty/short input bypasses Command entirely, so it cannot invalidate pending repository work. Replace just that suggestions orchestration with a cancelable 500ms Timer plus `_lastSuggestionInput` text for debounce admission (not execution authority). On text change, cancel timer and immediately call loadSuggestions.invalidate() BEFORE the delayed valid fetch; empty/short input dispatches `.run(text)` immediately for no-op success. Valid input schedules one run after 500ms. Repeated builder calls for same text do not restart timer. Retain controller ownership, history chips, short-input empty `_lastOptions`, existing mounted guards and captured VM callback safety. Build the suggestions ListenableBuilder immediately and observe command.results for skeleton/success/error, without awaiting repository completion; remove `_currentQuery`, `_search` post-fetch options and Debounceable-based request orchestration. Keep unrelated debounce utility unchanged. dispose cancels this timer before disposing internal controller; callbacks capture references and check mounted plus current VM ownership (didUpdateWidget cancels old timer and resets input cache on VM/controller replacement). Empty input renders history; 1–2 characters render current short-query empty options. A pending valid query can never repopulate state after short input, and a new valid edit makes old work stale even during its debounce window. Debounce reduces repository calls; superseding guarantees correctness.
